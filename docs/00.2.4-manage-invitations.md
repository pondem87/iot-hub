# Use case 3: Manage invitations

## use case 2.1: Accept account invitation

#### 1. Intent
- Accept invitation and join a hub account

#### 2. Primary Actor
- User account owner (human owner)

#### 3. Aggregate root
- Account/User

#### 4. Preconditions
- valid user must be logged in
- invitation must exist, not be cancelled and match loggedin userId

#### 5. Command/Inputs
- AcceptHubAccountInvitationCommand
    - invitation id

#### 6. State changes
- invitation accepted
- user added to hub account

#### 7. Invariants
- hub account must be active
- invitation must not be already accepted
- invitation must match logged in userId

#### 8. Domain Events
- InvitationAcceptedEvent

#### 9. Side effects
- add default roles

#### 10. Failure modes
- InvalidInvitationId
- AccountNotActive
- InvalidInvitationState

#### 11. Variants

---

## use case 2.2: Invite user to join hub account

#### 1. Intent
- Invite user to a hub account

#### 2. Primary Actor
- Hub account admin or user with create invitation permission

#### 3. Aggregate root
- Account/Invitation

#### 4. Preconditions
- valid user must be logged in
- hub account must be active
- invitation must not already exist or must be cancelled if it exists

#### 5. Command/Inputs
- InviteUserToAccountCommand
    - valid user phone number

#### 6. State changes
- invitation created

#### 7. Invariants
- hub account must be active

#### 8. Domain Events
- InvitationCreatedEvent

#### 9. Side effects
- invitation notification sent to invited user

#### 10. Failure modes
- InvalidUserIdentity
- AccountNotActive
- InvitationAlreadyAccepted

#### 11. Variants
if invitation already exists
- resend notification
if invitation exists and is cancelled
- reactivate invitation
- resend notification
if invitation is revoked
- create new invitation

---

## use case 2.3: Cancel account invitation

#### 1. Intent
- Cancel user invitation to a hub account

#### 2. Primary Actor
- Hub account admin or user with write permission for invitation

#### 3. Aggregate root
- Account/Invitation

#### 4. Preconditions
- must be logged in as admin or user with correct permission
- invitation must exist and not be cancelled or revoked

#### 5. Command/Inputs
- CancelHubAccountInvitationCommand
    - invitation id

#### 6. State changes
- invitation cancelled

#### 7. Invariants
- hub account must be active
- invitation must not be already accepted

#### 8. Domain Events
- InvitationCancelledEvent

#### 9. Side effects
- invitation cancellation notification sent

#### 10. Failure modes
- InvalidInvitationId
- AccountNotActive
- InvitationAlreadyAccepted
- InvalidInvitationState

#### 11. Variants
